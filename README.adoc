= Metanorma standoc document models

Consolidated monorepo of the document models and grammars for the Metanorma
standoc document family — Basicdoc, Standoc, and every flavour — per
https://github.com/metanorma/metanorma-core/issues/16[metanorma-core#16].
This repository replaced the former per-flavour `metanorma-model-*`
repositories; their commit histories are preserved here.

[IMPORTANT]
.Prime directive — the models are the LML files
====
The information models of this repository are the **LML files**:
`<flavour>/models/*.lml` and the LutaML definition modules they include.
They are the single source of truth for the document models.

The RNC/RNG grammars in `grammars/` are **implementation files that
accompany the models** — hand-maintained artifacts, slated for retirement
by the model-driven programme (issue #181: schemas and classes generated
from the LML models).

This MUST NOT be violated: never treat RNC grammars as the model
definitions; never describe, edit, or restructure this repository as if
the grammars were the models. When a model changes, the LML changes
first; the grammars follow.
====

== Layout

`grammars/`::
The shared RNC/RNG grammar hub (formerly `metanorma-model-iso`). The
shared-layer grammars are named after their layer — `standoc.rnc`,
`standoc-presentation.rnc` — with per-flavour grammars alongside. It
aggregates the unified relaton-models repository (all former
per-flavour relaton-model-* repos, merged 2026-08) plus basicdoc and
requirements models as git submodules.

`<flavour>/`::
Per-flavour information models (LutaML) and documentation, one directory
per former `metanorma-model-<flavour>` repository: `bipm`, `bsi`, `cc`,
`csa`, `gb`, `ieee`, `iho`, `iso`, `itu`, `m3aawg`, `mpfa`, `nist`,
`ogc`, `ribose`, `standoc`, `un`.

The repository has a single root `Gemfile` (rake, lutaml-lml, lutaml-xsd,
ruby-jing) and a single root `Rakefile` — per-flavour Gemfiles and build
scripts are deliberately not a thing.

== Building the grammars

Two scripts in `grammars/` with strictly separated concerns, plus one
shared vendoring helper:

* `./make.sh` — deterministic build. Vendors the `.rnc` inputs from the
  checked-out submodule pins (via `scripts/vendor-submodule-grammars.rb`),
  compiles everything to `.rng` with trang, and runs the validation suite.
  Never updates submodules, never writes `versions.json`. Requires
  submodules to be initialized (`git submodule update --init --recursive`).
* `./refresh-submodules.sh` — the only network path: updates submodules
  to their remotes, checks out `main` in each, and records versions in
  `versions.json`. Run manually when pulling in a new upstream release,
  then run `./make.sh`.
* `scripts/vendor-submodule-grammars.rb` — the single implementation of
  submodule → `grammars/` vendoring. Called by both `make.sh` and the
  Pages deploy workflow.

Trang is resolved in order: the `TRANG_JAR` environment variable, a
`trang` on `PATH` (e.g. Homebrew), or a one-time build of the pinned
upstream ref `V20241231` under `grammars/vendor/` (gitignored; cacheable
in CI). No more clones of jing-trang's drifting `main`.

CI enforces a **regeneration parity gate**: the committed `.rng`
artifacts must be byte-identical to regeneration output from the pinned
sources. Hand-edits to generated artifacts, or source changes committed
without regenerating, fail the build.

== Model diagrams

`<flavour>/models/*.lml` are the single source of the model diagrams;
`<flavour>/images/*.png` are committed generated output. From the repo
root:

  rake            # all flavours
  rake iso        # one flavour
  rake verify     # assert every committed .png really is a PNG
  rake clean

== Model catalogue and LXR schema packages

The Pages workflow (`.github/workflows/deploy.yml`) publishes two layers to
GitHub Pages from each flavour's `build-config.yml`:

* the **model catalogue** — `rake site` renders `site/` (ERB templates) into
  `_site/`: a clause-numbered index of the base layer and every flavour,
  with per-flavour pages showing each diagram card, its grammar companion
  and a link to its schema browser;
* the **LXR schema packages** — one `.lxr` grammar package + SPA per flavour
  built with `lutaml-xsd`, overlaid under `<flavour>/` alongside the
  catalogue.

Flavour diagrams are **fully encapsulated** (same convention as
relaton-models#70): a flavour view includes only its own module's models;
classes from other layers render as collapsed, name-only boxes. The
`standoc/` base views are the exploded reference set. `rake parity` guards
the layout invariants.

== Vendoring

Flavour gems vendor the compiled RNG (`grammars/copy.sh`, run from a
workspace with gem checkouts as siblings). Destination filenames use the
post-rename `standoc.*` names and gem-local legacy names (e.g.
`isostandard.rng`) because gem code loads those paths; the bridge retires
with generated-schema loading (issue #181).

== Where work happens

* Grammar work: PRs against `grammars/` here. Grammar issues live in
  this repository's tracker (open issues from the former
  `metanorma-model-iso` and flavour model repositories were transferred
  here at consolidation).
* Model-driven architecture (LML as single source of truth, generated
  schemas and classes, retiring hand-maintained RNC and Trang/Jing):
  see issue #181 — the follow-on programme to this consolidation.

The `semx`/`fmt` Presentation XML contract is documented in
`grammars/README.adoc`.
